# 验收标准模板

> 验收是收尾款的关键节点，模糊的验收 = 拖延的尾款。
> **验收清单要在合同签订时就写明，不在交付时才提出。**

---

## 通用验收原则

1. **可量化**：每条验收项都能用 ✅/❌ 判断，不留模糊地带
2. **可演示**：客户在自己的环境里能复现
3. **有时限**：交付后 3 天内验收，否则视为通过
4. **有截图**：每条验收点都附截图/视频

---

## 模板 1：网页爬虫验收清单

### 功能验收

- [ ] 命令 `python main.py --url <目标> --output result.csv` 能成功执行
- [ ] 输出文件包含字段：[标题、URL、正文、发布时间、抓取时间] 等约定字段
- [ ] 至少抓取 X 页 / Y 条数据，无重复
- [ ] 每条数据的字段完整率 ≥ 95%（缺失字段允许，但需明确标注）
- [ ] 失败页面记录在单独的 `errors.log` 中，含 URL 和失败原因

### 合规验收

- [ ] 程序遵守 robots.txt（可在日志中看到读取记录）
- [ ] 请求间隔 ≥ 1 秒（可通过日志验证）
- [ ] User-Agent 透明可识别（如包含联系邮箱）
- [ ] 跳过敏感路径（/login, /admin, /payment 等）

### 文档验收

- [ ] README 包含：项目简介、依赖、运行命令、参数说明、示例输出
- [ ] requirements.txt 列出所有依赖
- [ ] 提供至少 1 个示例输出文件（脱敏）
- [ ] 提供 30-60 秒的演示视频

### 测试验收

- [ ] 提供 ≥ 5 个 pytest 测试用例
- [ ] 测试覆盖：成功抓取、失败重试、速率限制、字段提取
- [ ] `pytest` 运行 100% 通过

## 模板 2：FastAPI 后端验收清单

### 功能验收

- [ ] 所有约定的 API 端点都返回正确的 HTTP 状态码
- [ ] Swagger UI（/docs）能正常打开，所有接口可在浏览器中调用
- [ ] 数据库迁移脚本能在空数据库上重建完整 schema
- [ ] 错误请求返回标准化的错误响应（含 error code、message、timestamp）

### 安全验收

- [ ] JWT/Session 机制正常（登录-访问保护接口-退出）
- [ ] 密码使用 bcrypt 加密存储（数据库中肉眼不可读）
- [ ] SQL 注入测试通过（用 `' OR 1=1 --` 测试登录）
- [ ] CORS 配置正确（前端域名白名单）

### 性能验收

- [ ] 单接口响应时间 ≤ 200ms（在客户提供的服务器上）
- [ ] 并发 10 个请求无错误（ab/wrk 测试）
- [ ] 内存占用稳定（运行 10 分钟无明显增长）

### 部署验收

- [ ] `docker compose up` 一行命令启动
- [ ] 提供 `.env.example`，列出所有需配置的环境变量
- [ ] README 含部署到云服务器的步骤
- [ ] 客户在自己的服务器上能跑起来（视频会议演示）

### 文档验收

- [ ] README 完整
- [ ] 接口文档（Swagger 自动生成）
- [ ] 数据库 ER 图（手绘或 dbdiagram.io）
- [ ] 部署 Runbook（生产环境运维手册）

## 模板 3：数据分析报告验收清单

### 数据验收

- [ ] 数据来源说明（爬取 / 客户提供 / 公开数据集）
- [ ] 数据清洗规则文档化（去重、空值处理、异常值过滤）
- [ ] 清洗前后的数据量对比（如：原 10000 条 → 清洗后 8500 条，删除原因列出）

### 分析验收

- [ ] 至少 X 个核心指标（客户约定的 KPI）
- [ ] 每个指标有：定义、计算方式、数值、趋势、解读
- [ ] 包含异常点标注（哪天 / 哪个值偏离正常，原因猜测）

### 报告验收

- [ ] Markdown / HTML 格式
- [ ] 至少 X 张图表（柱状图、折线图、热力图等）
- [ ] 图表清晰：标题、坐标轴、单位、图例、数据标签
- [ ] 含 Executive Summary（300 字以内的核心结论）
- [ ] 含数据来源、分析方法、局限性说明

### 可复现性验收

- [ ] 提供 Jupyter Notebook 或 Python 脚本
- [ ] 客户在同样的数据上能复现一致结果
- [ ] 中间结果（数据集、模型）可下载

## 模板 4：RAG 知识库验收清单

### 检索验收

- [ ] 客户提供的 X 篇文档能成功导入
- [ ] 同义词查询能返回相关结果（如"假期"和"年假"返回相同段落）
- [ ] 检索结果含来源（文档名、页码或段落 ID）
- [ ] Top-K 检索精度抽样测试 ≥ 70%（10 个测试问题至少 7 个返回正确段落）

### 回答验收

- [ ] 答案基于检索段落生成（不"幻觉"无依据内容）
- [ ] 答案末尾或文中含引用回链
- [ ] 没有相关内容时回答"我不知道，建议查阅..."（而非编造）
- [ ] 流式输出（SSE）正常，首字延迟 < 1 秒

### 私密性验收

- [ ] 文档数据不离开客户环境（私有化部署）
- [ ] 不向第三方 API 发送原始文档（如 OpenAI 仅接收摘要 / 检索结果）
- [ ] 用户问答日志可关闭或本地存储

### 部署验收

- [ ] Docker Compose 一键启动
- [ ] 客户能在自己的服务器上跑起来（视频会议演示 + 手把手教学）
- [ ] 含基础监控（接口延迟、错误率）

## 验收流程

### 1. 交付前自检

- 你自己跑一遍所有验收点，截图存档
- 录制 60 秒演示视频

### 2. 交付时

- 邮件 / 微信发送：源代码 + 测试报告 + 验收清单 + 演示视频
- 内容："请按附件清单验收，3 天内未提出异议视为通过。"

### 3. 客户验收中

- 客户提出问题：分类
  - **A. 合同范围内的 Bug**：免费修复
  - **B. 合同范围外的需求**：明确告知"这是新需求，需要单独报价"
  - **C. 模糊地带**：争取"达到主要功能"即通过，详细优化进入下一期

### 4. 验收通过

- 客户书面/邮件/微信回复"验收通过"
- 你回复："感谢确认，请在 3 天内支付尾款 ¥X，到账后 1 周内提供后续支持。"

### 5. 验收争议

- **不要立即妥协也不要立即翻脸**
- 列出争议项，逐条对照合同
- 在合同范围内的，承认并修复
- 不在合同范围内的，引用合同条款拒绝
- 必要时引入平台仲裁（猪八戒、码市等都有仲裁机制）

---

## 关键提醒

1. **验收清单 = 合同附件**：必须在合同签订时就写明
2. **不要交付不完整版本**：宁可晚 1 天，不要交一个有 5 个 bug 的"差不多版"
3. **录屏 = 证据**：交付时录一个完整跑通的视频，客户后期反悔时是关键证据
4. **3 天验收期**：超过 3 天未异议视为通过——这条**写进合同**
5. **尾款不到账，源代码不上传**：这是底线
