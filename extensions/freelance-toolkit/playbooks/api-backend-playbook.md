## 接单类型

### 1. 小程序后端（¥3000-15000）

**典型客户**：独立小程序开发者、小公司

**典型需求**：

- 微信小程序 + 后端 API（约 15-30 个接口）
- 含登录（微信授权）、用户管理、商品/订单/评论 CRUD
- MySQL/PostgreSQL 持久化

**用项目 2 改造的重点**：

- 主要复用 `app/` 的目录结构
- 替换 RAG 部分为业务接口
- 加微信小程序登录（需要 `wxapppy` 包）

**升单技巧**：

- 加支付（微信支付 / 支付宝） = +¥3000
- 加图片/视频上传到 OSS = +¥1500
- 加管理后台（HTMX + FastAPI） = +¥3000

**报价区间**：

- 简单（10 接口，无支付）：¥3000-5000
- 标准（20 接口，含支付）：¥8000-12000
- 复杂（30+ 接口，含管理后台）：¥15000+

---

### 2. 独立前端 / 设计师的 API 后端（¥5000-20000）

**典型客户**：独立 React/Vue 前端开发者、UI 设计师转开发

**典型需求**：

- 客户已经做了前端原型，缺后端
- 需要 RESTful API + 数据库 + 部署
- 通常含一些 webhook 集成（Stripe、Twilio、ChatGPT API）

**优势**：

- 这类客户**很懂技术、付款爽快**
- 一旦合作好可以**长期接他后续项目**

**用项目 2 改造的重点**：

- 完全保留 `app/main.py` 的 FastAPI 应用结构
- 加 CORS 配置（允许前端域名）
- 加 Stripe / OpenAI 等第三方 SDK 封装

---

### 3. 数据 API / 内部工具 API（¥3000-15000）

**典型客户**：数据团队、运营团队

**典型需求**：

- 内部数据查询 API（基于已有数据库）
- 把 Excel / 数据库变成可用的 API
- 给 BI 工具 / 自动化工具提供数据接口

**优势**：

- 业务逻辑简单（主要是查询）
- 可标准化（一套模板服务多个客户）

---

### 4. AI 应用后端（¥8000-30000）

**典型客户**：内容创作者、教育机构、电商运营

**典型需求**：

- ChatGPT API 封装（含限流、日志、计费）
- 文章/短视频脚本生成
- 自动客服 / 邮件分类

**用项目 2 的优势**：

- 项目 2 的 LangGraph + SSE 直接复用
- 加 OpenAI / Claude / 国内大模型 SDK 切换
- HTMX 前端可以直接给客户看 demo

**报价区间**：

- 简单封装（10 个 prompt 模板）：¥8000
- 中等（含数据库、用户系统、计费）：¥18000
- 复杂（多模型路由、Agent 工作流）：¥30000+

---

### 5. 旧系统 API 化 / 迁移（¥10000-50000，谨慎）

**典型客户**：传统行业老板（5-50 人公司）

**典型需求**：

- 把 Excel 表格 / 单机软件变成在线系统
- 把 PHP/Java 旧系统迁移到 Python
- 老 API 重写

**为什么谨慎**：

- 需求会**无限延伸**（"既然你都做了，能不能再加 X"）
- 客户技术认知低，不容易接受合理报价
- 测试和文档要求最高

**接的话**：

- 必须严格分阶段，每阶段独立验收
- 每阶段独立合同 + 付款

## 第 1 单实战路径

## 标准交付物

每个 API 项目交付时，必须包含：

| 文件                 | 说明                                    |
| -------------------- | --------------------------------------- |
| `README.md`          | 项目说明、安装、运行                    |
| `docker-compose.yml` | 一键启动                                |
| `.env.example`       | 环境变量列表                            |
| `app/main.py`        | FastAPI 入口                            |
| `app/routes/`        | 接口实现                                |
| `app/models.py`      | Pydantic 模型                           |
| `app/db/migrations/` | 数据库迁移脚本                          |
| `tests/`             | pytest 测试（覆盖率 ≥ 70%）             |
| `app/docs/`          | API 业务说明（Swagger 自动生成 /docs）  |
| `deploy/`            | 部署说明（生产环境、Docker Compose）    |
| `videos/demo.mp4`    | 30-60 秒演示视频                        |

## 长期合作的种子

### 1 单变 10 单：从"开发"升级为"运维"

第一次交付后，主动 follow-up：

- "您的服务运行情况怎么样？"
- "如果有新接口需求，可以包月运维 ¥1500-3000/月"
- "数据量上来后可能需要加缓存，预估 ¥3000 升级"

### 1 单变 N 单：模板化

把不同客户共性的部分做成 **starter template**：

- `fastapi-mini-app-starter`（小程序后端模板）
- `fastapi-rag-starter`（RAG 知识库模板）
- `fastapi-internal-tool-starter`（内部工具模板）

下次有类似需求，**1 天就能交付**，单价不变 → 时薪 ¥1000+

## 客户最常见的"伪需求"

接单前必须**追问 5W1H** 避免踩坑：

| 客户说               | 实际意思                 | 你应该问                            |
| -------------------- | ------------------------ | ----------------------------------- |
| "做个简单的 API"     | 涉及 50 个接口           | "具体需要哪些功能？大概多少接口？"  |
| "和某 SaaS 类似就行" | 想要那家 5 年的产品      | "您要的核心功能是哪 3 个？"         |
| "支持高并发"         | 实际 QPS < 10            | "预计并发用户数？峰值在什么时段？"  |
| "性能要好"           | 数据库选型不重要         | "用户数预估？数据量？查询频率？"    |
| "用户体验要好"       | 想要漂亮 UI 但你只做后端 | "前端是您团队做？我只做 API 是吗？" |
| "用最新技术"         | 要 GPT-4 / Vector DB     | "为什么需要 X？解决什么具体问题？"  |

## 避坑清单

1. ❌ **不接报价 < ¥3000 的 API 单**——做不出能交付的水平
2. ❌ **不接"按效果付费"**——成单率/转化率不可控
3. ❌ **不接"先免费试用"** 哪怕客户说"试用满意再签合同"
4. ❌ **客户提供服务器你部署的，写好风险条款**——服务器挂了不是你的问题
5. ❌ **不在第一次沟通就 100% 信任客户**——50% 预付保命
6. ✅ **接每一单都让客户提供"成功验收标准"**——白纸黑字
7. ✅ **每一次部署都做备份 + 回滚演练**——免得客户改坏了赖你
8. ✅ **保留所有沟通记录** ——微信/邮件/平台站内信，至少 1 年

## 进阶：从"接单的"到"被求着接单的"

完成 5-10 个 API 项目后：

### 1. 写技术文章

- "FastAPI 项目避坑 10 件事"
- "我用 FastAPI 替代 Django 的 5 个理由"
- "小程序后端选型对比：Node / FastAPI / Spring Boot"

### 2. 开源 starter template

- 把项目 2 抽象成 `fastapi-rag-starter`
- 100 stars 以上自然有客户找上来

### 3. 录 YouTube / B 站系列

- "用 FastAPI 14 天做出一个 SaaS"
- 自然吸引同样想做 SaaS 的潜在客户

### 4. 涨价的逻辑

- 第 1-3 单：¥3000-5000，重点是评价
- 第 4-10 单：¥8000-15000，开始有底气拒单
- 第 10 单后：¥15000+，挑客户而不是被客户挑
- 1 年后：¥30000+，开始转向"做自己的产品"
