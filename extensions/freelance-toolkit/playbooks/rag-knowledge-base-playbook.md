> **最高客单的方向**。¥10000-50000+/项目。需要前两个方向铺垫，但回报最大。

- ✅ 学完 Stage 4-5（L51 RAG + L52-L57 Agent）+ 项目 2
- ✅ 已经有 5+ 单 API 后端经验，能稳定交付
- ✅ 沟通能力好，能跟非技术老板讲清楚 AI 价值

## 为什么这是金矿（也是火坑）

### 金矿

- 2025-2026 年中国中小企业**普遍想做 AI 但不知道怎么做**
- 律所、教培、医疗、电商客服都是**强需求**
- 每家公司至少有 50-500 篇内部文档没消化
- 客户预算高（年度 IT 预算的 1-3%）

### 火坑

- 客户**期望管理极差**（看到 ChatGPT 视频以为他公司也能 5 分钟搞定）
- 数据洁净度差（PDF 扫描件、Excel 乱码、Word 嵌套图片）
- 评估标准模糊（"我感觉答得不准"很难量化）
- 私有化部署 → 你要会 Docker / K8s / Linux 运维

## 接单类型（按客单价）

### 🥉 入门版（¥10000-20000）

**典型客户**：

- 50 人以下小公司
- 明确知道自己要"AI 客服"或"AI 知识库"
- 已经在用 ChatGPT，但希望接入自己的资料

**典型需求**：

- 50-200 篇文档
- 1 个对外/对内问答界面
- 能上传文档 + 提问
- 内存向量库（不要求企业级持久化）

**交付物**：

- HTMX 前端 + FastAPI 后端
- 文档上传 + 切分 + 向量化（首批客户提供）
- Mock LLM 兜底 + OpenAI / 国产大模型可切换
- Docker Compose 部署
- 30 分钟培训视频

**工期**：14-21 天

---

### 🥈 标准版（¥25000-40000）

**典型客户**：

- 100-500 人公司
- HR / 法务 / 财务 / 知识管理部门
- 有一定 IT 团队（但不会自己做）

**典型需求**：

- 文档量不限（≥1000 篇）
- 多用户 + 权限管理
- 引用回链 + 来源高亮
- SSE 流式回答
- 私有化部署到客户内网
- 含 1-3 个月运维支持

**交付物**：

- 项目 2 升级版 + Qdrant 持久化
- LangGraph 多步推理（先检索 → 评估相关性 → 生成 → 校对）
- 用户系统（基于 L35 安全网关）
- 数据看板（接入次数、问答记录、用户活跃）
- 现场部署 + 培训
- 3 个月内的 Bug 修复 + 8 小时支持/月

**工期**：30-45 天

---

### 🥇 旗舰版（¥50000+）

**典型客户**：

- 500+ 人企业
- 律所 / 三甲医院 / 高校 / 大型电商
- 数据敏感度高（绝不能用云端 LLM）

**典型需求**：

- 完全私有化（含本地 LLM，如 Ollama + Llama 3 / Qwen）
- 对接现有 OA / CRM / SSO 系统
- 多租户 / 多部门隔离
- 中英双语 / 多文档格式（PDF/Word/Excel/PPT/扫描件 OCR）
- 审计日志 + GDPR 合规

**交付物**：

- 完全定制（项目 2 只是起点）
- 现场调研 → 数据治理 → 模型选型 → 部署 → 培训 → 运维
- 6-12 个月运维合同

**工期**：60-90 天 + 持续

**门槛**：

- 你**必须有 1-2 个真实落地案例**
- **必须有公司主体**（个人接 ¥50000+ 大企业不签）
- **必须有团队后备**（你病了项目不能停）

## 第 1 单实战路径（最现实路线）

### 阶段 1：把项目 2 改造成"垂直行业 Demo"（2 周）

**选 1 个细分行业**做深度 demo（重要：不要做通用版）。

#### 推荐选项：

| 行业                 | 数据来源                   | 价值点           |
| -------------------- | -------------------------- | ---------------- |
| **小红书运营答疑**   | 公开运营文档、爆款笔记规律 | 内容创作者市场大 |
| **跨境电商客服**     | 亚马逊政策文档、退款规则   | 客户预算高       |
| **教培机构教师答疑** | K12 / 公考 / 考研真题      | 培训机构遍地     |
| **法务咨询入门**     | 公开判例、合同范本         | 单价高           |
| **医美咨询助手**     | 项目说明、术后护理         | 转化高           |

> ⚠️ 法务/医疗有合规风险，**只做"咨询入门"+免责声明**，不做诊断/法律建议。

#### 改造步骤：

```bash
cd projects/02-ai-fullstack-capstone

# 1. 收集 50-100 篇你选定行业的公开文档
# 2. 用项目 2 的导入接口批量导入
# 3. 改 HTML / CSS 让 UI 看起来"是这个行业的"
#    - 配色、Logo、欢迎词、示例问题
# 4. 部署到 Railway，绑定一个看起来专业的域名
#    - lawyer-helper.top
#    - ecommerce-cs.top
# 5. 录 5 分钟视频：
#    - 客户痛点（30秒）
#    - 演示 5 个真实问答（3 分钟）
#    - 后台架构 + 私有化能力（1 分钟）
#    - 联系方式（30 秒）
```

### 阶段 2：5 条精准询价（2 周）

**目标客户来源**：

- 即刻搜"找人做 AI"
- 公众号文章评论区（搜"我们公司也想做"）
- 小红书 / 抖音搜"AI 知识库"，看评论
- LinkedIn 搜"知识管理总监"

**话术模板**（按 `templates/07-cold-outreach.md`）：

```
[姓名] 您好，

我是做 AI 知识库系统的 Python 开发者，最近做了一个 [你的行业 demo]，
专门针对 [行业] 的常见问题答疑。

地址：[demo URL]
视频：[5 分钟演示]

注意到您 [具体观察，比如最近发布的某篇文章 / 公司招聘"知识管理"岗位]，
不知道贵司是否也有类似需求？

特点：
1. 完全私有化（数据不出公司）
2. 支持本地 LLM（OpenAI 不可用时仍可工作）
3. 含引用回链（可追溯到原文档）

如果您有兴趣，我可以**上门免费做一次需求调研**（北京/上海/远程），
2 小时左右，无需任何承诺。

[你的名字]
[作品集 URL]
[公司案例（如有）]
```

### 阶段 3：第一单成交（2 周）

收到询价 → 见面/视频会议 30-60 分钟：

#### 第一次会议必须问清楚的 10 个问题

1. **数据规模**：多少篇文档？多少 GB？
2. **数据类型**：PDF / Word / Excel / 图片？多少是扫描件？
3. **使用场景**：内部员工 / 对外客户？多少日活？
4. **核心问题**：希望解决"5 大常见问题"还是"无限拓展"？
5. **大模型偏好**：能用 OpenAI 吗？还是必须本地？
6. **部署偏好**：公网托管 / 客户云 / 客户内网？
7. **数据敏感度**：是否含个人信息 / 商业秘密 / 法律责任？
8. **预算**：粗略范围？（如果客户不愿说，给三档让选）
9. **时间**：什么时候要上线？
10. **决策人**：今天来开会的能拍板吗？

> 💡 **关键**：第 7、8、10 问决定**你接不接这个单**。
>
> - 数据敏感度高 → 必须报旗舰版（¥50000+）
> - 预算 < ¥10000 → 不接
> - 决策人不在现场 → 委婉推后续，直到决策人参与

### 阶段 4：报价 + 签约 + 50% 预付 + 开干

按 `templates/01-quote-tiered.md` 报三档，给客户 3 天选择期。

合同必须明确：

- **数据由客户提供**（提供时间晚 → 工期相应延后）
- **客户内部审核期**（客户内部要 N 天，不算你工期）
- **本地 LLM 模型由客户决定**（你只承诺集成，不承诺模型效果）
- **运维支持范围**（不含数据更新 / 不含新增功能）

## 项目实施关键节点

### Week 1：架构 + 数据治理

```
Day 1-2: 客户访谈 + 调研文档
Day 3-4: 架构图 + 数据库 ER + 部署方案
Day 5-7: 数据清洗（PDF 提取文字、Excel 解析、OCR 扫描件）
```

#### 数据治理是最大的坑

**90% 的 RAG 项目延期，都是数据问题**：

- 客户给的 PDF 是扫描件 → 要做 OCR
- Word 里有嵌套表格 → 文本提取失败
- Excel 单元格合并 → 结构化破碎
- 文档命名混乱 → 标题/作者/日期没法自动提取

**应对**：

- **报价前**抽样 5-10 个客户文档，亲自试一遍
- 在合同里写"数据准备阶段（5-7天），由客户配合提供清洗后的版本，否则按 ¥1000/天 加价"

### Week 2-3：后端开发

基于项目 2 改造：

- 文档导入接口 → 加批量导入
- 向量库 → 切到 Qdrant 持久化
- 检索 → 加 reranker（提高精度）
- 回答 → LangGraph 多步：检索 → 评估 → 生成 → 校对
- LLM → 双模式（OpenAI / 本地 Ollama）

### Week 4：前端 + 集成

- HTMX UI → 加用户管理
- SSO 集成（如果有）
- 上传组件（拖拽 / 批量）
- 后台管理（管理员视图）

### Week 5：部署 + 培训

- 生产环境部署（Docker Compose / K8s）
- 监控告警（Prometheus + Grafana 简易版）
- 客户培训（2-4 小时视频会议 + 文档）
- 验收

---

## 客户验收的 5 个关键指标

让客户提供 **20-50 个测试问题**（必须客户出，不是你出）：

| 指标       | 标准   | 测量方式                           |
| ---------- | ------ | ---------------------------------- |
| 检索召回率 | ≥ 70%  | 测试题中"该返回的"段落是否在 Top-5 |
| 回答相关性 | ≥ 80%  | 客户主观打分（1-5 星）             |
| 引用准确性 | ≥ 90%  | 引用的段落是否真的支持回答         |
| 首字延迟   | ≤ 2 秒 | 浏览器 DevTools 测                 |
| 回答完整性 | ≥ 70%  | 测试题中"完整答案"占比             |

> 💡 **关键**：这 5 个指标在合同里写明**目标值** + **测试方法**。否则客户会用感觉说"答得不好"，你赢不了。

## 避坑清单

### 技术坑

1. ❌ **不要承诺 100% 准确**——RAG 本质是概率
2. ❌ **不要用 Notion / Obsidian 类客户私有平台 API**——他们 API 限速严
3. ❌ **不要把所有文档存到 1 个 collection**——多租户隔离很关键
4. ❌ **不要直接用客户的 OpenAI Key**——他们的 quota 用完会怪你
5. ❌ **不要在第一版做"完美方案"**——MVP 上线后迭代
6. ✅ **始终保留 Mock LLM 模式**——客户网络出问题时仍能 demo
7. ✅ **每个回答必带"数据来源"链接**——这是客户判断质量的唯一直接方式
8. ✅ **保留全量问答日志**——客户验收时拿出来跑指标

### 商务坑

1. ❌ **不接"模糊范围"的单**——必须明确文档数、问题类型、用户数
2. ❌ **不接"按效果付费"** ——RAG 效果天花板由数据质量决定，你控制不了
3. ❌ **不接"先做一个测试版"** ——除非测试版独立报价
4. ❌ **不签"无限期支持"**——明确 3-6 个月，到期再续
5. ❌ **不在客户内网做开发**——开发在你这，部署到客户那
6. ✅ **每个里程碑独立验收 + 付款**——分 3-4 期：调研、原型、上线、运维
7. ✅ **数据治理时间** 单独计费 + 单独工期
8. ✅ **本地 LLM 模型选型** 让客户决策，避免承担效果责任
