## 一、设计理念

### 1.1 核心目标

为零基础学员提供清晰的**能力成长路线图**，让每个人知道：
- **现在在哪**：当前处于哪个能力阶段
- **要去哪**：下一个能力阶段的里程碑
- **怎么走**：需要掌握哪些知识点

### 1.2 能力阶段模型

| 阶段 | 名称 | 能力目标 | 能做什么 | 典型项目 |
|------|------|----------|----------|----------|
| **S0** | 编程入门 | 理解代码逻辑 | 读懂简单脚本 | Hello World |
| **S1** | 基础开发 | 独立写工具脚本 | 自动化办公、数据处理 | 批量重命名脚本 |
| **S2** | 工程实践 | 写出规范代码 | 参与团队项目、通过 code review | CLI 工具库 |
| **S3** | Web 开发 | 前后端全栈 | 构建 CRUD Web 应用 | 博客系统 |
| **S4** | 架构能力 | 高并发/微服务 | 企业级系统 | 电商后端 |
| **S5** | 数据工程 | 数据管道 | ETL、分析、可视化 | 日志分析平台 |
| **S6** | AI Agent | 智能应用 | LLM 应用、Agent 系统 | RAG 问答系统 |
| **S7** | 专家级 | 系统设计 | 复杂系统架构 | 多租户 SaaS |

## 二、知识点三级分类标准

### 2.1 层级定义

```
Level 1: 概念（Concept）
  └─ 是什么、为什么需要
  └─ 面试问：解释什么是...

Level 2: 操作（Operation）  
  └─ 怎么用、什么场景用
  └─ 面试问：如何使用...

Level 3: 实现（Implementation）
  └─ 底层原理、最佳实践
  └─ 面试问：实现原理是...
```

### 2.2 示例：异步编程

| 层级 | 知识点 | 面试问题 |
|------|--------|----------|
| L1 | 协程的概念 | 什么是协程？与线程的区别？ |
| L1 | 事件循环机制 | 事件循环是如何工作的？ |
| L2 | async/await 语法 | 如何定义和调用异步函数？ |
| L2 | asyncio.run() | 何时使用 asyncio.run()？ |
| L2 | create_task / gather | 如何并发执行多个协程？ |
| L3 | 协程调度原理 | 协程是如何被调度的？ |
| L3 | CancelledError 处理 | 如何正确处理取消异常？ |

### 2.3 示例：FastAPI

| 层级 | 知识点 | 面试问题 |
|------|--------|----------|
| L1 | RESTful 架构 | 什么是 RESTful API 设计原则？ |
| L1 | 依赖注入模式 | 为什么需要依赖注入？ |

| L2 | Pydantic BaseModel | 如何验证请求数据？ |

| L3 | Pydantic 验证原理 | Pydantic v2 的验证机制？ |

## 三、课程能力映射标准

### 3.1 课程元数据结构

```yaml
课程编号: L14
课程名称: 并发编程入门
能力等级: S1 → S2  # 从 S1 提升到 S2

# 学完能做什么（能力产出）
capabilities:
  - [x] 使用 async/await 编写异步代码
  - [x] 区分同步和异步函数的使用场景
  - [x] 处理异步错误和取消

# 前置知识（必须已掌握）
prerequisites:
  - L04: 函数定义与参数传递
  - L08: 异常处理基础

# 核心知识点（三级粒度）
knowledge:
  level1:
    - [协程] 协程的概念与优势
    - [事件循环] 事件循环机制
    - [并发模型] 并发 vs 并行
  level2:
    - [异步语法] async def / await
    - [异步运行] asyncio.run()
    - [任务管理] create_task / gather
    - [异步上下文] async with
  level3:
    - [调度原理] 协程调度机制
    - [错误处理] CancelledError 处理
    - [异步迭代] async for / __aiter__

# 软依赖（建议掌握）
soft_prerequisites:
  - L15: 函数式编程（高阶函数概念）
```

## 六、质量标准

### 6.1 知识点命名规范

```
格式：[技术域] 操作名称

规则：
1. 使用动宾短语：创建协程、设计 API
2. 避免歧义：不用 "async" 用 "异步协程"
3. 统一前缀：同领域使用相同前缀
4. 控制长度：每个知识点 ≤ 20 字

示例：
✅ [异步] 协程创建
✅ [类型] 泛型约束
❌ 协程
❌ 如何使用泛型
```

### 6.2 依赖关系规范

```
硬依赖（必须满足）：
  A → B 表示：掌握 A 才能学习 B
  不能有环路

软依赖（建议满足）：
  A ≈ B 表示：掌握 A 会更容易理解 B
  不影响学习路径
```

### 6.3 DAG 验证规则

| 检查项 | 规则 | 判定 |
|--------|------|------|
| 环检测 | 无循环依赖 | 必须通过 |
| 深度检测 | 最长依赖链 ≤ 10 | 警告 |
| 孤立检测 | 无前置也无后置的节点 | 确认合理性 |
| 重复检测 | 同一知识点多定义 | 合并 |
