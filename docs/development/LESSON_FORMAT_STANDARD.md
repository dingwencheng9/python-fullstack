## 一、设计背景与问题

### 1.1 问题背景

通过深度分析 100 个 lesson.md 文件，发现课程形态差异巨大：

| 形态 | 数量 | 行数 | 示例 |
|------|------|------|------|
| **极简占位型** | 13 | 14-50 | Stage A-8 新课 |
| **骨架待补型** | 15 | 50-200 | Stage 4/8 规划中 |
| **标准完整型** | 50+ | 200-1000+ | Stage 0-3/5-6 |
| **高阶工具型** | 若干 | 100-150 | Stage 8 DevOps |

**核心矛盾**：用同一套标准套用所有课程，既浪费资源，也不适用。

### 1.2 解决方案

引入**分级标准体系**，按课程形态选用不同标准：
- 最小化强制，只强制必要结构
- 渐进增强，低级别可平滑升级
- 工具支持，自动检查评分

## 二、级别定义与判定

### 2.1 三级标准

| 级别 | 适用场景 | 强制章节 | 推荐行数 | 软性上限 |
|------|---------|---------|----------|----------|
| **Core** ⭐ | 占位课程/大纲 | 3 个 | 15-60 | ≤100 |
| **Standard** ⭐⭐ | 进阶/工具类 | 6 个 | 200-600 | ≤800 |
| **Extended** ⭐⭐⭐ | 核心/入门课程 | 10 个 | 500-2000 | ≤2500 |

### 2.2 判定决策树

```
课程行数 ≤ 50 行？
├─ 是 → Core（占位课程）
└─ 否 → 继续判断

是 Stage 0 课程？
├─ 是 → Extended（强制）
└─ 否 → 继续判断

课程行数 ≥ 500 行 + 完整元数据？
├─ 是 → Extended
└─ 否 → 继续判断

有 2+ 个 Part + 实战案例 + 自检清单 + 常见陷阱？
├─ 是 → Extended
└─ 否 → Standard
```

### 2.3 行数软性指导原则

> ⚠️ **重要说明**：以下原则为软性指导，非强制限制。内容完整性优先于行数限制。

1. **内容完整性优先**：如果 2000 行能完整呈现主题，不要为了满足行数限制而拆分
2. **代码密度影响规模**：代码密集型课程（装饰器、类型系统）自然更长；概念型课程（HTTP、安全）可以更简洁
3. **拆分阈值建议**：超过 2000 行时"建议考虑拆分"，但非强制
4. **按需拆分**：拆分应基于主题自然边界，而非行数限制

**拆分判断标准**：
- 主题是否可以独立学习？
- 拆分后是否有明显的内容空洞？
- 学员需要跨越多个文件学习的成本？

**示例**：
- L02 运算符+控制流 (1630 行)：建议保持不拆分，主题关联性强
- L20 装饰器 (1583 行)：建议保持不拆分，内容已整合良好

### 2.4 Stage 适配表

| Stage | 推荐级别 | 行数范围 | 说明 |
|-------|---------|----------|------|
| Stage 0 | **Extended（强制）** | 800-2000 | 零基础入门，完整教学 |
| Stage 1-2 | Extended/Standard | 500-1800 | 推荐 Extended |
| Stage 3 | Extended/Standard | 500-1500 | 推荐 Extended |
| Stage 4 | Standard | 300-1000 | Web 进阶，工具为主 |
| Stage 5 | Extended | 500-1800 | 数据工程，推荐完整教学 |
| Stage 6 | Extended/Standard | 500-2000 | AI Agent 基础 |
| Stage A | Standard/Core | 200-800 | AI 进阶，可精简 |
| Stage 8 | Standard/Core | 200-800 | DevOps，工具类 |

## 六、Extended 标准结构变体

### 6.1 两种结构模式

Extended 标准支持两种结构模式，课程可根据内容特点选择：

#### 模式 A: 独立章节式（传统）

适合内容相对独立、需要强调各部分区别的课程。

```markdown
## 🎯 学习目标
## 📖 课程导读
## Part 1: {主题名}
## Part 2: {主题名}
## 🎓 核心知识点总结
## 💡 常见陷阱与最佳实践
## 🚀 实战案例
## 📚 延伸阅读
## ✅ 自检清单
## 🔗 下一步
```

**特点**：
- 各章节独立，结构清晰
- 适合内容关联度较低的课程（如 L02 运算符）

#### 模式 B: 总结内嵌式（推荐）

适合内容关联紧密、需要整体总结的课程。

```markdown
## 🎯 学习目标
## 📖 课程导读
## Part 1: {主题名}
## Part 2: {主题名}
## 🚀 快速开始
## 📝 练习题
## 📝 本章总结
  ### 核心知识点
  ### 常见陷阱
  ### 实用技巧
  ### 典型应用场景
## 💭 课堂思考
## 📚 参考资料
## ✅ 完成标准
## 🔗 下一步
```

**特点**：
- 总结内嵌在 `## 📝 本章总结` 下
- 内容衔接更自然（如 L11 生成器）
- 适合技能递进型课程

#### 判定原则

| 课程类型 | 推荐模式 | 示例 |
|---------|---------|------|
| 知识点并列型 | 模式 A | L02 运算符、L03 数据结构 |
| 技能递进型 | 模式 B | L11 生成器、L14 并发编程 |
| 工具使用型 | 模式 A | L18 工具链、L31 Docker |

### 6.2 内容 > 格式原则

**核心原则**：内容充实性优先于格式标准化。

| 情况 | 处理方式 |
|------|----------|
| 内容充实、格式不完全符合 | ✅ 保持内容，补充缺失标题 |
| 格式完整、内容空洞 | ❌ 扩充内容，不要形式主义 |
| 有内容无标题 | ⚠️ 添加正式标题以便检查 |

**示例**：
- L08 异常处理：8.7 节有检查清单 → 添加 `## ✅ 自检清单` 标题
- L11 生成器：使用模式 B 且内容充实 → 保持现有结构
